# 2026-09-18

## openkylin/openkylin:3.0 容器桌面 VNC 配置验证（codespace-desktop 仓库）

对 `.devcontainer` 中基于 `openkylin/openkylin:3.0` + UKUI + TigerVNC + noVNC 的配置做了实机构建/运行验证，
修复后可在容器形成可用图形桌面（实测 RFB 3.8 握手 + 密码认证成功，noVNC 6080 返回 200，UKUI 会话正常加载）。

### 实证得到的关键结论（openKylin 3.0 特有的坑）
1. 基础镜像**不含 `dpkg-dev`**，UKUI 多个包的 preinst 依赖 `dpkg-architecture`，不装会解包失败。
2. 容器内无 systemd，`kylin-nm` 的 postinst 检测到 systemctl 就调用且返回非 0，
   连累 `ukui-desktop-environment` 元包失败。基础镜像本身没有 systemctl，
   但安装过程中 systemd 包会引入并覆盖普通 stub —— 必须用 `dpkg-divert` 占位。
3. **不能执行 `apt-get upgrade -y`**：源里 `libimobiledevice6` 与 `libimobiledevice-1.0-6`
   争抢 `/usr/lib/aarch64-linux-gnu/libimobiledevice-1.0.so.6` 且互不声明 Conflicts，必然解包失败。
4. TigerVNC 1.15 用 `~/.config/tigervnc`（XDG 路径），而 openKylin 的 perl 5.36 中
   `File::Copy` 未导出 `mv`，导致旧目录 `~/.vnc` 的迁移必然失败、`vncserver` 直接退出。
   规避办法：启动前就让 `~/.config/tigervnc` 存在，跳过迁移逻辑。
5. `vncserver` 经 update-alternatives 指向 `tigervncserver`（支持 `-geometry -depth -localhost no`）；
   `vncpasswd` 指向 `tightvncpasswd`（支持 `-f`），由 `tightvncserver` 依赖自动引入，无需显式安装。
6. `useradd` 不是软件包名，提供它的是 `passwd` 包。
7. `COPY` 沿用宿主机权限位，脚本必须显式 `chmod 755`，否则 bash 读不到而以 Permission denied 失败。
8. openKylin 官方源偶发 502 Bad Gateway，需 `Acquire::Retries` + 重试循环。

### 本机环境注意事项
- 项目位于 `/Volumes` 外置卷，macOS 会生成 `._Dockerfile` 等 AppleDouble 文件，
  本地 `docker build` 会报 `failed to xattr ._Dockerfile`，需复制到干净目录再构建。
- 本机 Docker Desktop 已配国内镜像加速器，可拉取 Docker Hub 镜像；直连 hub.docker.com 的 curl 会超时。

### 最终交付与实测结论
`.devcontainer/Dockerfile`、`vnc-start.sh`、`devcontainer.json` 三个文件已按上述结论修复并写回仓库。
用成品镜像（3.5GB）实测通过：`Xtigervnc :1` 监听 5901、noVNC 监听 6080（vnc.html 返回 200）、
RFB 003.008 协商出 [19,2]、`password` 通过 DES 挑战响应认证成功，
UKUI 三件套 ukui-session / ukui-panel / peony-qt-desktop 均存活。

连接口：GitHub Codespaces 的 PORTS 面板打开 6080 的转发地址访问 vnc.html，密码 `password`。
注意：容器中会出现 `[ukui-settings-d] <defunct>` 等少量僵尸子进程，属正常，不影响桌面。
另：README 仍描述为 Ubuntu 24.04 + Cinnamon，与实际代码（openKylin 3.0 + UKUI）已不一致（未改动）。
